# DUG Track 업로드 · 코멘트 · TC 규칙

상세 규칙 전체는 같은 폴더의 `workflow.md`(필독). 핵심만:

- **확인 전 쓰기 금지:** 생성·수정·삭제·코멘트·시트 수정은 대상 목록과 올릴 문구를 보여주고 사용자가 "올려/ㅇㅇ/네"로 확인한 뒤에만 실행한다. 초안 수정 요청을 받으면 반영본을 다시 보여주고 재확인을 받는다. "왜 안 했냐" 같은 질문은 실행 지시가 아니다.
- **프로젝트·모듈:** RVRFLIVE(project_id `060ef029-15c7-4e48-bdc9-6ebe07e0176a`), 기본 모듈은 workflow.md 기준(다른 모듈 지정 시 그쪽).
- **양식:** 버그는 고정 템플릿(발생위치·재현스텝·기대결과·특정조건·발생경우, 상태 Issue Open), 아이디어/FunQA는 가설+제안 템플릿(상태 Idea/FunQA). 카테고리 분류, 말투(간결체·쿠션어), "버그에 딸린 제안은 특정조건에 한 줄"도 workflow.md대로.
- **해결 확인 코멘트:** `<App> <채널> v<버전> 해결 확인` 한 줄. 빌드는 슬랙 #22_qa-채널((채널명으로 검색)) 최신 빌드 공지를 직접 읽어서 쓴다(버전을 되묻지 않음). 상세는 workflow.md.
- **TC 시트:** Issue Testing / Issue Fixed / In Progress만 Fail 기록, 남의 기록은 덮어쓰지 않고 추가만. 상세는 workflow.md §3~5.
- **동향 근거가 필요한 아이디어 초안**은 `rvrf-trend-search`로 건수·인용을 먼저 뽑는다.

사용자별 값(user id 등)은 DUG Track `get_me`로 확인한다.
